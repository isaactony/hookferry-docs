---
title: "Forward provider webhooks to your local app"
description: "Register a Hookferry source URL with a webhook provider such as a payments or Git platform and receive its real events on localhost."
---

This guide connects a real webhook provider, such as a payments platform or a Git host, to an app running on your machine. To try Hookferry with a `curl` request first, see the [Quickstart](/quickstart).

## Prerequisites

- The Hookferry CLI, installed and signed in. See [Install the Hookferry CLI](/installation).
- An app running locally with a route that accepts `POST` requests, for example `http://localhost:3000/webhooks/billing`.
- Permission to add a webhook endpoint in your provider's dashboard or API.

<Steps>
  <Step title="Start a listen session on a named source">
    Use a source name that describes the provider and environment. The CLI creates the source if it doesn't exist.

    ```bash
    hookferry listen 3000 --source billing-dev --path /webhooks/billing
    ```

    Copy the **Source URL** and the **Secret** from the output.
  </Step>

  <Step title="Register the source URL with the provider">
    In the provider's webhook settings, add a new endpoint and paste the source URL, for example `https://in.hookferry.dev/src_9fK2mQ7wLx`. Select the event types you want to receive.

    <Tip>
      The source URL doesn't change when you restart `hookferry listen` with the same `--source` name. You only register it once.
    </Tip>
  </Step>

  <Step title="Store the signing secrets in your app's environment">
    Your app now receives two signatures: the provider's own signature and the `Hookferry-Signature` header. Add the secrets to a `.env` file that isn't committed to source control:

    ```bash .env
    PROVIDER_WEBHOOK_SECRET=paste_the_provider_secret_here
    HOOKFERRY_SIGNING_SECRET=whsec_3c1b7f0e9a5d4c2b8e6f
    ```

    To write the verification code, see [Verify webhook signatures in Node.js and Python](/guides/verify-signatures).
  </Step>

  <Step title="Trigger a test event from the provider">
    Most providers have a **Send test event** button in their webhook settings. Use it, or perform a real action in the provider's test mode.

    The listen session prints a line for each event, and your app receives the request.
  </Step>
</Steps>

## Keep one source per provider and environment

Create separate sources, such as `billing-dev` and `git-dev`, instead of sending several providers to one source. Separate sources keep event lists readable and let you replay one provider's events without touching another's.

## When you stop the listen session

Events that arrive while no session is running are stored with the status `undelivered`. When you start the session again, replay them:

```bash
hookferry replay --source billing-dev --status undelivered --yes
```
